## Установка и запуск

okama Planner строит помесячные денежные потоки семьи и прогноз методом Монте-Карло. Поддерживается Python 3.11 и новее. Для экспорта в Excel установите дополнения `reports`. Конфигурация разработки использует Python 3.14; при работе над кодом явно выберите этот интерпретатор:

```bash
git clone https://github.com/mbk-dev/okama-planner.git
cd okama-planner
poetry env use python3.14
poetry install --extras reports
poetry run python examples/localized_plan.py --output-dir tmp/localized-example
```

Пример не требует загрузки рыночных данных, браузера или клиентской базы. В нём используются вымышленные суммы в USD и зафиксированные синтетические месячные доходности. Расчёт выполняется один раз с `seed=42`, сохраняет `request.json` и `result.json`, затем создаёт `plan-en.xlsx`, `plan-ru.xlsx`, `plan-de.xlsx`, `plan-es.xlsx`, `plan-zh.xlsx` и интерактивные автономные файлы `forecast.html` в каталогах `linear/` и `log/` каждого языка. Откройте HTML локально, чтобы посмотреть портфель и чистый капитал. Во всех пяти версиях одинаковые суммы в USD, допущения и численные результаты. Начальное значение генератора не фиксирует зависимости: сохраняйте версии окружения для точного повторения.

Выберите отдельные версии параметром `--languages en ru`. Добавьте `--image-format png` или `--image-format svg` для статичных графиков, если установлен Chrome или Chromium; параметр `--browser-executable /path/to/chromium` задаёт исполняемый файл браузера. Для HTML и Excel браузер не нужен.

## Подготовка плана

Возьмите за основу [вымышленный запрос](../../examples/baseline-request.json). Передайте полный запрос функции `forecast(request)` из `okama_planner`. `plan.t0` задаёт первый месяц; укажите горизонт, год выхода на пенсию, активы, обязательства, ежемесячные доходы и расходы. Для каждой цели задайте уникальный `goal_id`, подпись `label`, вид `kind`, текущую стоимость `amount_pv`, год оценки `pv_year` и целевую дату. Ставки и вероятности задаются долями: `0.02` означает 2 %. Доходы и расходы вводятся положительными суммами; в реестре денежных потоков расходы получают отрицательный знак.

`currency="USD"` задаёт валюту расчёта. `language="ru"` в `export_report` или `export_charts` выбирает русское оформление. Язык не конвертирует деньги и не меняет инфляцию, доходности портфеля или допущения о законодательстве. Пользовательские подписи сохраняются как введены; переведите их самостоятельно для другой версии. В [правилах локализации](../localization.md) описаны поддерживаемые сообщения, форматы и настройка языка при запуске MCP.

Одновалютный запрос использует одну валюту. Мультивалютный запрос явно задаёт `reporting_currency`, группы `currency_groups` в исходных валютах и валютные допущения; локализованные отчёты сохраняют валюты групп и валюту представления. См. [мультивалютное планирование](../multicurrency.md) и [режимы портфелей](../portfolio-modes.md). Локализация не добавляет отсутствующие во входных данных налоги и комиссии или неподдерживаемые поля gamma/alpha в запрос прогноза.

## Чтение и сохранение результатов

Суммы в отчётах и графиках номинальные: индексация следует заданным ставкам. Инфляция не переводит суммы графиков в постоянную покупательную способность автоматически. На логарифмической шкале нулевые и отрицательные значения пропускаются, а затронутые диапазоны имеют разрывы; для этих периодов смотрите линейный график.

Экспорт использует сохранённые снимки запроса и результата без повторного расчёта:

```python
import json
from pathlib import Path
from okama_planner.reports import export_report
from okama_planner.charts import export_charts

folder = Path("tmp/localized-example")
request = json.loads((folder / "request.json").read_text())
result = json.loads((folder / "result.json").read_text())
export_report([{"label": "Synthetic USD", "request": request, "result": result}],
              folder / "review.xlsx", language="ru")
export_charts(result, folder / "review", language="ru")
```

Правка чисел в книге не пересчитывает Монте-Карло. Чтобы изменить план, измените входные данные, повторите `forecast` и сохраните новые снимки перед экспортом. Пересчитайте итоговые формулы Excel перед использованием их кэшированных значений. Храните исходный JSON и сведения о происхождении расчёта рядом с экспортом.

## Локальный реестр и конфиденциальность

Необязательный реестр SQLite локально хранит клиентов, версии планов, сценарии и сохранённые результаты. Имена и контакты держите в реестре; в общих материалах обозначайте клиентов кодами реестра. Базы и реальные клиентские документы храните вне публичного Git. Локализация меняет отображаемые тексты; имена таблиц и столбцов SQL, ключи JSON, значения перечислений и технические идентификаторы остаются стабильными. Настройка базы и примеры API описаны в [руководстве по хранению](../storage.md).
