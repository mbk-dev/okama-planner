# Граница персональных данных между Planner и ИИ

По запросу владельца личные данные не должны выходить из Planner через MCP. Аудит выявил полные записи в client_get/list/create/update и обход защиты ошибок в английском режиме.

Planner предоставляет отдельный модуль ai: только коды клиентов и персональных полей, финансовые входы с кодами вместо свободных названий, ошибки без исходных значений. Доверенный PlannerStore остаётся локальным API для человека; MCP его не импортирует. Настоящие имена, контакты и примечания вводятся локально через python -m okama_planner.private_clients из JSON-файла, вне чата/MCP. MCP не создаёт и не меняет личные поля.

Сохранение и загрузка финансового плана выполняются внутри Planner по коду клиента и номеру версии, без SQL, таблиц, внутренних ID или пути к БД в контракте ИИ. При сохранении по ИИ-API записывается обезличенный план. Старые доверенные планы обезличиваются до возврата. Финансовые значения, связи целей с активами и даты сохраняются.

Прогноз выполняется на обезличенном входе. Результат подписывается процессным HMAC для экспорта: произвольный результат или изменённые поля отвергаются до создания отчёта. Экспорт через ИИ всегда обезличен и использует нейтральный бренд, без локального логотипа или контактов. Человеческий API отчётов остаётся прежним. MCP не возвращает абсолютные пути. После перезапуска прогноз для экспорта нужно получить заново.

Граница относится к предоставленным MCP/API инструментам. Доступ ИИ к оболочке, файлам или Python под той же учётной записью не изолируется этим контрактом; для такого доступа требуется отдельный процесс/учётная запись и права на БД. Уже отправленные в чат данные нельзя скрыть обратным преобразованием. Это зафиксировано в руководстве, без обещания абсолютной анонимности: финансовые суммы и демография остаются доступны для расчёта.
