# okama Planner 0.5.1 — local interfaces in every supported language

0.5.1 translates the human interfaces into every language Planner already supports. The
client form, the meeting journal and the legacy database viewer now ship in **English,
Russian, German, Spanish and Simplified Chinese**, with English as the default. Nothing in
the calculation, storage or AI boundary changes; existing databases and plans need no
migration.

## Interfaces

```bash
python -m okama_planner.client_form --database /private/planner.sqlite3 --language de
```

- `--language` accepts `en`, `ru`, `de`, `es` and `zh` and defaults to **English**. The same
  language applies to the intake form, the meeting journal and the read-only legacy viewer.
- Dates, month names and the date picker follow the selected locale; amounts and enum values
  keep their technical codes in the database and are translated only for display.
- One caption catalogue (`src/okama_planner/ui_texts.csv`) holds all five languages. The
  server sends its caption table to the browser bundle, so the React journal carries no
  translations of its own and a new string cannot drift between the Python and JavaScript
  layers.
- The legacy viewer translates field labels, enum captions, section headings and metric rows,
  including `probability_of_success`, survival and percentile metrics.
- Missing captions, a language short of a caption or Russian text reaching a non-Russian
  interface fail the test suite instead of shipping.

## Compatibility

- Requires Python >=3.11 and okama >=4.0.0; validated with okama 4.0.1.
- Pair with okama-mcp >=3.1.0,<3.2 and Planner `>=0.5.0,<0.6.0`; 0.5.1 keeps the 0.5 contract
  and database schema.
- No storage migration: open an existing database directly.
