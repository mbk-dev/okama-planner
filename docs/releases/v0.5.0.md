# okama Planner 0.5.0

This release publishes the privacy-capable Planner interface required by okama-mcp.
It includes the existing changes since 0.4.1; the forecasting engines are reused.

- `okama_planner.ai` sanitizes AI-facing inputs and outputs, owns client database
  operations and signs anonymous forecast results for report export. Invalid or
  modified results fail closed. Names and contacts stay in human-operated local tools.
- Local client storage supports versioned plans and anonymous forecasts through MCP.
- Five-language presentation, the human-only intake form and legacy LFP viewer
  are included. The legacy database remains a separate read-only human surface.
- Requires Python >=3.11 and okama >=4.0.0. Install `okama-planner[reports]` for Excel.

## Compatibility

Use okama-mcp >=3.1.0,<3.2 with Planner >=0.5.0,<0.6.0. Planner 0.4.1 lacks the
AI boundary; MCP rejects its local integrations instead of exposing personal data.
The 0.5 minor version identifies this contract change explicitly.

## Release verification

Both the wheel and sdist must contain `ai.py`, `privacy.py`, storage migrations,
the empty SQLite template, the terminology table and offline chart assets.
The template must contain no business records. Release assets include SHA256SUMS
and the tracked-source extraction manifest. Package-pair acceptance is recorded
in [LFP #84](https://github.com/mbk-dev/lfp/issues/84) and
[MCP #6](https://github.com/mbk-dev/okama-mcp/issues/6).

[Changes since 0.4.1](https://github.com/mbk-dev/okama-planner/compare/v0.4.1...v0.5.0)

## One database and client journal

- Adds opaque CRM identifiers and a persistent human-only meeting journal, using
  the selected visual/Markdown editor with local bundled assets.
- Schema 0003 unifies client identity and complete advisory planning history in
  one SQLite file. Earlier native snapshots migrate to `planner_*` tables without
  replacing client codes. The verified importer retains all source columns, rows
  and historical relationships and rejects conflicts atomically.
- Adds `PlannerClientAccess`: anonymous read-only by default, explicit local opt-in
  for full personal CRUD through Planner. MCP never performs direct database access.
- See [migration and access policy](../unified-database.md). The packaged template
  contains no client records; real data and backups are excluded from Git.
